# 게임 검증 기록과 체크리스트

[README](../README.md)의 정적 검사와 별도로, 실제 Warcraft III에서 사용자가 확인한 결과를 기록한다. 도구의 테스트는 Lua 재파싱·Fengari 실행·MPQ 재읽기까지만 증명한다.

## 2026-10-07 솔로 플레이 확인

입력은 `LoTKT/dist/LoTKT 2.4E.w3x`(맵 SHA-256 `7fb4bd96153b66560160d534bae4e9a9cd90e63aff464ab3c18d59de89612e63`)다. 다섯 사본을 배틀넷에서 솔로로 플레이했다.

| 사본 | 설정 | World Editor | 배틀넷 솔로 플레이 |
| --- | --- | --- | --- |
| A | `--preset protect` | 열림 | 이상 없음 |
| B | `--preset hardened` | 열림 | 이상 없음 |
| C | `--preset maximum` (당시 4 KiB sector) | 열림 | 이상 없음 |
| D | `--preset protect --sector-size-shift 7` | 열림 | 이상 없음 |
| E | `--preset maximum --clean-editor --clean-development --clean-editor-data --cleanup-contract cleanup/lotkt-2.4e-2026-10-06-editor-data-contract.json --sector-size-shift 7` | 열림 | 이상 없음 |

이 결과로 64 KiB sector(shift 7)를 `maximum` 프리셋에 포함했다. 다른 shift 값은 확인하지 않았다.

다섯 사본은 MPQ 이름을 UTF-8 바이트로 해시하도록 바꾸기 전(`main` `0f39e41` 이전)의 코드로 만들었다. 그 뒤로는 한글 등 ASCII가 아닌 import 경로의 파일도 재압축한다. 입력에 그런 파일이 있으면 같은 설정이라도 출력이 이 기록과 다르므로 다시 확인한다. `(listfile)`을 지우지 않는 설정(예: `--check --preset protect --details`)으로 실행하면 파일별 절감 표에서 해당 파일 이름과 재압축 여부를 볼 수 있다. `maximum`은 `(listfile)`을 지우므로 표에 이름 대신 블록 번호가 나올 수 있다.

확인하지 않은 항목은 다음과 같다.

- 2인 이상 멀티플레이 동기화(desync)
- 원본으로 저장한 데이터를 보호 사본에서 불러오기와 그 반대
- 원본 대비 로딩 시간·FPS·메모리
- 모든 트리거·퀘스트·보스 경로의 개별 확인 결과(솔로 플레이에서 이상을 발견하지 않았다는 기록만 있음)

World Editor는 모든 사본을 열었다. 이 도구는 에디터 열기 방지를 제공하지 않는다. 에디터 데이터 정리와 `(listfile)` 삭제 뒤에도 지형·오브젝트 데이터는 남으며, 트리거 정의·영역·카메라·사운드·import 목록만 사라진다.

## 2026-10-07 World Editor 열기 차단 확인

입력은 위와 같은 `LoTKT 2.4E.w3x`다. 작업 브랜치 `claude/eloquent-maxwell-6p3fwm`으로 만들도록 안내한 사본이며(`maximum`·F는 `3e13251`, F1~F4는 `289368d`), 사용자가 Windows 화면에서 최대 보호 프리셋과 2.4E 검토 계약으로 만들고 확인했다.

| 사본 | 설정 | World Editor | 배틀넷 솔로 플레이 |
| --- | --- | --- | --- |
| `maximum` | 최대 보호 프리셋만 선택(열기 차단 꺼짐) | 경고 없이 열림 | 이상 없음 |
| F | 열기 차단 `version`·`both` | 메모리를 크게 사용하다 에디터가 스스로 종료 | 미확인 |
| F1 | 열기 차단 `version`·`wtg` | "응용 프로그램에 예기치 않은 오류가 발생했습니다."로 종료 | 이상 없음 |
| F2 | 열기 차단 `version`·`wct` | 열림 | 이상 없음 |
| F3 | 열기 차단 `truncated`·`both` | "응용 프로그램에 예기치 않은 오류가 발생했습니다."로 종료 | 이상 없음 |
| F4 | 열기 차단 `empty`·`both` | "파일을 불러올 수 없습니다 … 트리거 데이터가 없거나 잘못되었습니다."로 열기 거부 | 이상 없음 |

이 표의 사본은 Windows 화면에서 만들었다. 당시 화면은 최대 보호 프리셋을 고를 때 **선택적 문자열 숨김** 체크박스를 끄는 결함이 있어(`616a6f9`에서 수정), 사용자가 직접 켜지 않았다면 런타임 문자열 숨김 없이 만들어졌다. 열기 차단 결과에는 영향이 없다.

차단은 `war3map.wtg`가 결정했고 `war3map.wct`는 영향을 주지 않았다. 정상적인 오류 메시지로 거부한 `empty`를 기본 형태로 정했다. `empty`·`wtg` 단독 대상과 멀티플레이는 확인하지 않았다.

## 2026-10-07 모든 리터럴 숨김 확인

입력은 위와 같은 `LoTKT 2.4E.w3x`다. 작업 브랜치의 `87d5736` 패키지로 만들도록 안내한 사본이며, 사용자가 Windows 화면에서 최대 보호 프리셋, **선택적 문자열 숨김**, 고급 설정의 **모든 문자열 리터럴 런타임 숨김**을 켜고 만들어 배틀넷 솔로로 확인했다.

| 확인 항목 | 결과 |
| --- | --- |
| 스킬, 아이템 생성, 유닛 오더(이동·공격·시전) | 이상 없음 |
| 모델·아이콘·사운드 표시와 재생 | 이상 없음 |
| 툴팁·메시지 색상 코드와 숫자 표기 | 이상 없음 |
| 첫 스킬 사용·첫 UI 표시 때 순간 멈춤 | 느끼지 못함 |

멀티플레이 동기화와 로딩 시간·FPS 측정은 확인하지 않았다.

## 2026-10-07 0.8.0 화면·미리 복원 확인

입력은 위와 같은 `LoTKT 2.4E.w3x`다. `main`의 `6335979`(0.8.0) 패키지로 만들도록 안내한 사본이며, 사용자가 Windows 화면에서 만들고 확인했다.

| 확인 항목 | 결과 |
| --- | --- |
| 고급 설정의 세 탭과 메인 화면 **에디터 열기 차단** 체크박스 | 이상 없음 |
| 최대 보호 + 메인 화면 **에디터 열기 차단** 사본의 World Editor 거부·배틀넷 솔로 플레이 | 이상 없음 |
| 최대 보호 + **런타임 문자열 로딩 중 미리 복원** 사본의 로딩 시간·첫 사용 멈춤 | 미리 복원 없는 사본과 체감상 큰 차이 없음. 측정하지 않아 확실하지 않음 |

미리 복원은 체감으로 비교했으며 로딩 시간을 측정하지 않았다. 기본값 꺼짐과 프리셋 미포함을 유지한다.

## 2026-10-09 Reforged 3.0 맵 형식 확인 (정적)

`LoTKT/dist/LoTKT 2.4F.w3x`를 MPQ로 읽기만 해서 확인했다. 게임 실행 확인이 아니다.

| 항목 | 값 |
| --- | --- |
| `war3map.w3i` | 형식 39, 에디터 버전 7003, 게임 버전 3.0.1.24342, 스크립트 Lua |
| `war3map.wtg` | `WTG!`, 형식 `0x80000004`, 하위 버전 7 |
| `war3map.wct` | 형식 `0x80000004`, 하위 버전 1(14바이트) |

w3i 형식 39는 이미 지원 범위이므로 3.0 에디터로 저장한 이 맵에 맞춰 바꾼 코드는 없다. 이후 패치에서 새 형식이 나오면 도구는 추측하지 않고 거부한다.

## 다음 확인 체크리스트

사본을 만들 때 저장소 폴더에서 `git rev-parse --short HEAD`를 실행해 커밋을 함께 기록한다. 도구가 바뀌면 같은 설정이라도 출력이 달라질 수 있기 때문이다.

### 리소스

- [ ] 한글 등 ASCII가 아닌 경로로 import한 모델·텍스처·사운드·아이콘이 보호 사본에서 정상 표시·재생된다.

### 멀티플레이 (`maximum` 사본)

- [ ] 2인 이상으로 시작해 30분 이상 플레이하며 동기화 끊김이 없는지 확인한다.
- [ ] 여러 명이 동시에 스킬·아이템을 쓰고 보스전을 진행한다.
- [ ] 한 명이 저장·불러오기를 해도 다른 플레이어가 끊기지 않는다.
- [ ] 끝까지 진행해 승패 판정을 확인한다.

### 실험 옵션

- [ ] 기본 열기 차단(`empty`·`both`) 사본으로 2인 이상 멀티플레이를 진행한다.
- [ ] Warcraft III 패치 뒤 기본 열기 차단 사본이 여전히 오류 메시지로 거부되는지 확인한다.
- [ ] (선택) `--preload-strings` 사본과 기본 최대 보호 사본의 로딩 시간을 같은 PC에서 각각 세 번 이상 초시계로 재어 비교한다. 체감 비교에서는 차이를 확인하지 못했다.
- [ ] `--strip-media-metadata` 사본에서 효과음·배경음·반복 사운드가 원본과 같이 재생되는지 확인한다.
- [ ] `--hide-all-strings` 사본으로 2인 이상 멀티플레이를 진행한다.
- [ ] 런타임 문자열 사본에서 `GetLocalPlayer()` 조건 안에서만 쓰이는 텍스트(개인 메시지·로컬 UI·로컬 사운드)를 한 플레이어에게만 처음 표시한 뒤 계속 플레이해도 동기화가 끊기지 않는지 확인한다. 이때 복원과 캐시 생성이 그 플레이어의 클라이언트에서만 일어난다.

### 저장·불러오기

- [ ] 원본 맵으로 저장한 데이터를 보호 사본에서 불러온다.
- [ ] 보호 사본에서 새로 저장하고 다시 불러온다.

### 성능

- [ ] 전투가 많은 장면의 FPS를 원본과 비교한다.
- [ ] 장시간 플레이 후 메모리 사용량을 원본과 비교한다.
- [ ] 첫 스킬 사용·첫 UI 표시 때 순간 멈춤이 있는지 본다(런타임 문자열 첫 복원).

### 문제가 생기면

어느 사본에서 어떤 조작을 했을 때 발생했는지와 오류 메시지 원문을 기록한다. 원인 옵션은 다음 순서로 하나씩 해제해 찾는다.

| 증상 | 해제 옵션 |
| --- | --- |
| 로딩 실패·리소스 깨짐 | `--keep-sector-size` |
| 트리거·콜백 오작동 | `--no-rename-globals --no-rename-fields` |
| 엔진 함수 관련 오류 | `--no-hide-natives` |
| 유닛·아이템 생성 이상 | `--no-fold-fourcc` |
| 텍스트 이상·첫 사용 멈춤 | `--no-hide-strings` |
| 영역·카메라·사운드 이상 | 정리 옵션에서 `--clean-editor-data` 제외 |
